# Nglob Students · SolidJS + TypeScript

**Посмотреть:** распакуйте весь архив и откройте `OPEN_PREVIEW.html`. Переключатель показывает desktop 1440 px и mobile 390 px. Это одна адаптивная страница с работающими меню, окнами, FAQ и калькулятором. Интернет нужен только для перехода на сайт Nglob; документы в предпросмотре никуда не отправляются.

**Редактировать:** нужен Node.js 22.13+ и npm. В папке пакета:

```sh
npm ci
npm run dev
```

Проверка и выпуск обновлённого предпросмотра:

```sh
npm run typecheck
npm run build
npm run preview
```

`build` обновляет `preview/` и `OPEN_PREVIEW.html`. Готовая HTML-страница содержит текст до загрузки JavaScript. В `preview/` находится тот же интерфейс, который запускается через `npm run preview`; отдельной реализации мобильной версии нет.

## Встроить в сайт — четыре шага

1. Скопируйте `src/student/` в Solid-проект сайта и `public/nglob-students/` в его `public/`. Компонент сам подключает `student.css`; шрифт, header и footer наследуются от сайта.
2. На маршруте `/services/student-moves` разместите компонент между существующими header/footer. Он уже содержит один `<main id="main">`. В существующем общем footer используйте экспорт `approvedFooterGroups` из `src/student/navigation.ts`: это актуальные 11 ссылок в группах Services / Company / Partners / Support, совпадающие с предпросмотром. Сохраните оформление, логотип, социальные сети, платёжные обозначения и юридические ссылки общего footer. Готовые ссылки страницы и безопасная конфигурация экспортируются из модуля:

```tsx
import {
  StudentPage,
  studentLinks,
  unavailableVerification,
  exampleReferralConfig,
} from './student';

export default function StudentsRoute() {
  return (
    <StudentPage
      links={studentLinks}
      verification={unavailableVerification}
      referral={exampleReferralConfig}
    />
  );
}
```

3. В серверной разметке маршрута подключите `studentSeo` через head manager сайта, а `studentStructuredData` — как безопасно сериализованный JSON-LD. Компонент поддерживает SSR; применяйте SSR или prerender сайта. `src/demo/` и `preview/` — готовый предпросмотр, их оболочку в сайт копировать не нужно. `noindex` относится только к предпросмотру.
4. Подключите существующий сервер проверки через два метода ниже и передайте `mode: 'live'`. До этого `unavailableVerification` ведёт к контакту; он не имитирует успешную проверку. Ссылки на страницу политики и её короткое пояснение должны описывать реальную обработку документов.

## Контракт проверки студента

Полные типы: `src/student/types.ts`. Готовый интерфейс принимает один документ JPG/PNG/WebP/PDF размером от 1 байта до 10 MiB и показывает только ответ сервера.

```ts
import type { VerificationConfig, VerificationService } from './student';

// Реализация адаптера использует действующий API и авторизацию сайта.
// Имена endpoint, токены и формат загрузки компонент не задаёт.
export function liveVerification(
  service: VerificationService,
  privacyNoticeUrl: string,
  privacySummary: string,
): VerificationConfig {
  return { mode: 'live', service, privacyNoticeUrl, privacySummary };
}
```

| Метод сервиса | Вход | Результат |
| --- | --- | --- |
| `submit(file, { signal, idempotencyKey })` | Один `File`; сигнал отмены; ключ повторного запроса | `Promise<{ id, status, reason? }>` |
| `getStatus(id, { signal })` | ID принятой заявки; сигнал отмены | Тот же ID и актуальный `status` |

`status`: `received`, `reviewing`, `approved` или `rejected`. Непустой `id` — ID заявки текущего пользователя. `reason` — необязательное безопасное пояснение отказа. Ошибка транспорта отклоняет Promise; она не означает отказ в проверке.

Сервис проверяет авторизацию и принадлежность заявки, размер и содержимое документа на сервере; обеспечивает защищённую передачу, ограничения доступа, сроки хранения/удаление, отмену/тайм-аут и идемпотентность. Повтор отправки того же файла после ошибки использует тот же ключ. Решения принимает сервер; ручная кнопка обновления запрашивает новый статус.

Создавайте **один стабильный объект `VerificationConfig` на авторизованную сессию** и заменяйте его при смене пользователя/выходе. При закрытии окна файл и локальный preview удаляются, запрос отменяется; подтверждённые ID/статус остаются только в памяти этого экземпляра для повторного открытия. После перезагрузки страницы долговременный статус предоставляет аккаунт сайта. Компонент не записывает документы в localStorage/sessionStorage.

`mode: 'preview'` и его sample-состояния используются только в `src/demo/`. Реферальная модель использует распределяемые 12%: скидку другу и кредит пригласившему на услуги Nglob. `exampleReferralConfig` показывает пример распределения; изменённый слайдер не сохраняет настройку аккаунта. Для действующего расчёта тип `ReferralConfig` принимает `mode: 'confirmed'`, доступные в аккаунте доли, условия и пояснение базы расчёта. Студенческое предложение задаётся строкой `studentOffer`; компонент не придумывает процент студенческой скидки.

## Состав

- `src/student/` — импортируемая страница, окна, типы, ссылки, SEO и стили.
- `src/demo/` — самостоятельный пример с общей навигацией Nglob.
- `public/` — локальные фото, логотип, шрифт и его лицензия.
- `scripts/`, конфигурация и lock — воспроизводимая сборка.
- `preview/`, `OPEN_PREVIEW.html` — готовые desktop/mobile для просмотра без установки.

Сервер загрузки документов, авторизация и бронирование принадлежат действующему приложению Nglob и не включены в пакет страницы.
