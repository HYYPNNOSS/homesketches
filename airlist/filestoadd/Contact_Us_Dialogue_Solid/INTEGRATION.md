# Интеграция Contact Us в Solid.js

**Этот пакет заменяет предыдущую React-версию для проекта Solid.js.** Все компоненты `.tsx` используют Solid и не требуют React. Конкретные внешние зависимости и границы готовности описаны в [HANDOFF.md](./HANDOFF.md).

## 1. Компонент и ресурсы

Перенесите **всю папку `src/contact`**, сохранив её структуру. Точка входа:

```tsx
import ContactUsPage from './contact';
import type {
  CallbackRequest,
  TeamMessage,
  SubmissionResult,
  SubmissionContext,
  SubmissionHandler,
  StatusHandler,
  ContactUsPageProps,
} from './contact';
```

`ContactUsPage` доступен и как именованный экспорт. Состояния, эффекты, условная разметка и списки реализованы средствами Solid: `createSignal`, `createEffect`, `Show` и `For`. Браузерные события, наблюдатели и размеры окна подключаются после монтирования либо в обработчиках событий.

В проекте уже должен быть настроен компилятор Solid JSX. Для отдельного примера включён `vite-plugin-solid`; существенные настройки TypeScript:

```json
{
  "compilerOptions": {
    "jsx": "preserve",
    "jsxImportSource": "solid-js"
  }
}
```

`preserve` оставляет преобразование JSX компилятору Solid; `jsxImportSource` выбирает типы Solid. Это соответствует [официальной документации Solid по TypeScript](https://docs.solidjs.com/configuration/typescript).

`ContactUsPage.css` импортируется из компонента и использует обычный CSS, ограниченный `.nglob-contact`. Локальный шрифт имеет отдельное имя `NglobContactInter`. Для вёрстки не требуются сетевые запросы к сервисам шрифтов или иконок.

`assets.ts` импортирует изображения как URL-строки. SVG также должен импортироваться как URL, а не как JSX-компонент. Если сборщик проекта меняет это правило, настройте импорт как ресурса или адаптируйте `assets.ts`. CSS содержит относительные ссылки на локальные ресурсы; сохраняйте папку `assets` целиком.

В SolidStart подключайте `ContactUsPage` из компонента маршрута и сохраняйте обработку его CSS и локальных ресурсов средствами существующего проекта. Переносить демонстрационные `src/main.tsx`, `src/preview.css`, `index.html` и Vite-конфигурацию в SolidStart не нужно. Пример комплекта — отдельное Vite-приложение, а не готовый проект SolidStart. Компонент проверен через Solid `renderToString` и последующий `hydrate` в браузере; маршрутизация, SSR, гидратация и метаданные конкретного сайта всё равно требуют проверки после интеграции.

При дальнейших изменениях сохраняйте реактивность свойств: обращайтесь к `props.onTeamSubmit` и другим `props.*` непосредственно в реактивной области или через getter. Не деструктурируйте props при создании компонента. `createSubmission` принимает getters обработчиков именно для корректной замены обработчика родителем. Пояснение — в [официальной документации Solid о props](https://docs.solidjs.com/concepts/components/props).

## 2. Оболочка страницы

Компонент уже содержит шапку и подвал из утверждённого макета. `SiteChrome.tsx` можно заменить общими компонентами существующего сайта. При этом потребуется согласовать сетку, отступы, зоны прокрутки и мобильную высоту; автоматическое удаление шапки и подвала не предусмотрено.

На mobile сохранена исходная модель: оболочка высотой `100dvh`, внутренняя прокрутка `.scroll-region`, нижняя зона Chat с безопасными отступами. Не помещайте страницу без адаптации в ещё один контейнер фиксированной высоты или прокрутки. На desktop плавающая Chat появляется после ухода всего блока контактов выше экрана.

При наличии внешней шапки, нижней навигации или других элементов вне `.nglob-contact` интегратор должен включить их в модальную блокировку фона. В текущем компоненте `inert` применяется к его собственной оболочке. Проверьте мобильную клавиатуру, safe-area, сохранение фокуса и открытие помощника после изменения этой структуры.

## 3. Свойства страницы

Все обработчики необязательны. Отсутствие `onCallbackSubmit`, `onTeamSubmit` или `onAssistantMessage` сохраняет демонстрационный режим соответствующей отправки. Отсутствие status-обработчика не отключает подключённую отправку: при неизвестном результате вместо проверки статуса предлагается email.

| Свойство | Контракт |
|---|---|
| `onCallbackSubmit` | `SubmissionHandler<CallbackRequest>` |
| `onTeamSubmit` | `SubmissionHandler<TeamMessage>` |
| `onCallbackStatus` | `StatusHandler` для уже созданного callback-запроса |
| `onTeamStatus` | `StatusHandler` для уже созданного сообщения команде |
| `onAssistantMessage` | `(message, { signal }) => Promise<string>`; строка реального ответа помощника |
| `requestTimeoutMs` | Положительное конечное число миллисекунд; по умолчанию `30000` |
| `showDemoNotice` | `boolean`, по умолчанию `true`; отображение служебных полос |
| `className` | Дополнительный класс корневого контейнера |

Пример подключения уже реализованных обработчиков проекта:

```tsx
import ContactUsPage from './contact';
// Этот модуль пишет команда проекта: он обращается к вашему серверу.
import {
  submitCallback,
  checkCallbackStatus,
  submitTeamMessage,
  checkTeamMessageStatus,
  askAssistant,
} from './contact-service';

export default function ContactRoute() {
  return (
    <ContactUsPage
      onCallbackSubmit={submitCallback}
      onCallbackStatus={checkCallbackStatus}
      onTeamSubmit={submitTeamMessage}
      onTeamStatus={checkTeamMessageStatus}
      onAssistantMessage={askAssistant}
      showDemoNotice={false}
    />
  );
}
```

`contact-service` в комплект не входит. В примере нет готовых серверных адресов или ключей доступа. Значение `showDemoNotice={false}` предназначено для подключённой и проверенной интеграции; оно само не меняет поведение обработчиков.

## 4. Отправка форм

Данные передаются уже с удалёнными пробелами по краям:

```ts
interface CallbackRequest {
  phone: string;
  message: string;
  bookingReference?: string;
  preferredTime?: string;
}

interface TeamMessage {
  email: string;
  message: string;
}

interface SubmissionContext {
  requestId: string;
  signal: AbortSignal;
}

type SubmissionResult =
  | { status: 'received' }
  | { status: 'rejected' }
  | { status: 'unknown' };

type SubmissionHandler<T> = (
  data: T,
  context: SubmissionContext,
) => Promise<SubmissionResult>;

type StatusHandler = (
  requestId: string,
  context: { signal: AbortSignal },
) => Promise<SubmissionResult>;
```

Передавайте `requestId` серверу как ключ идемпотентности. Повтор одного запроса с этим ключом не должен создавать новое обращение. Сохраняйте связь ключа с результатом приёма, чтобы status-обработчик мог получить результат по тому же ID. Не используйте проверку статуса для новой отправки.

| Ответ обработчика | Отображение и следующее действие |
|---|---|
| `received` | Подтверждённое получение; новая отправка этой формы заблокирована |
| `rejected` | Подтверждённый неприём; Try again возвращает сохранённые поля для проверки и повторной отправки |
| `unknown` | Получение не подтверждено; новая отправка заблокирована, Check status вызывает отдельный обработчик с прежним ID |

Пока операция ожидает ответа, повторные вызовы блокируются. Исключение, сетевой тайм-аут или некорректный результат обработчика дают `unknown`, поскольку они не доказывают неприём сервером. Только явный `received` показывает подтверждение получения. Если обработчик статуса отсутствует, неизвестный результат предлагает уточнить получение по email через ссылку Email our team; для полноценной интеграции подключайте отправку и статус вместе. Существование почтового процесса проверяется в основном сайте.

Результат содержит только `status`. Интерфейс использует утверждённые тексты состояний, а не выводит произвольные ответы сервера. Возвращённые HTTP-ошибки и внутренние диагностические сообщения не показываются пользователю напрямую.

На клиенте проверяются обязательность, базовый формат телефона/email и длина сообщения до 1 000 символов. Проверку, нормализацию и ограничения повторите на сервере. Предпочтительное время звонка остаётся пожеланием; получение запроса не подтверждает время звонка.

Для отправки, проверки статуса и AI действует защитный срок ожидания `requestTimeoutMs`. По умолчанию — 30 000 мс; отсутствующее, неположительное или неконечное значение заменяется этим значением. Слишком большое значение ограничивается 2 147 483 647 мс, чтобы избежать переполнения таймера браузера. Это инженерная настройка интерфейса, а не согласованный SLA сервера. По истечении срока сигнал отменяется и ожидание интерфейса завершается даже при адаптере, игнорирующем отмену. Поздний ответ не меняет результат. Отправка формы переходит в `unknown`; её проверка использует прежний ID. AI сохраняет черновик и показывает ошибку с возможностью повторить попытку.

## 5. Помощник

`onAssistantMessage` получает текст и `AbortSignal`; должен вернуть строку ответа подключённого сервиса. Ответ выводится средствами Solid как обычный текст, без вставки HTML. Без обработчика показывается только демонстрационное уведомление — выдуманного ответа AI нет.

Во время ожидания ввод и отправка заблокированы. После ответа сообщение и ответ добавляются в переписку, черновик очищается. Ошибка или пустой ответ оставляют черновик и предлагают повторить попытку либо обратиться к команде. История и черновики хранятся только в памяти компонента; долговременное хранение и контекст серверной беседы реализует проект.

При размонтировании компонента ожидающие операции получают отмену через `AbortSignal`. Серверный адаптер должен передавать этот сигнал своему клиенту запросов. Секреты сервиса, доступ к заказам и отправка уведомлений остаются на сервере.

## 6. Перед выпуском

- Подключите нужные обработчики и проверьте получение, отказ и неизвестный результат; отдельно проверьте status-запрос по прежнему ID.
- Проверьте маршруты существующего сайта. Ссылки перенесены из утверждённого HTML, в том числе `Company details` → `/about#company-details`; целевые разделы этот комплект не создаёт.
- Согласуйте обработку обращений с действующей Privacy Policy и серверной авторизацией для данных заказа.
- После завершения интеграции настройте `showDemoNotice`, уберите демонстрационный `noindex,nofollow` из страницы-хоста и задайте production canonical средствами проекта.
- Проверьте desktop/mobile после подключения общей оболочки сайта. Официальные логотипы и изображения из `assets` сохраняйте без изменения формы и пропорций.

Для запуска заявлен Node.js >=22.13.0; конкретные результаты проверки приведены в QA-RU.md. Vite предоставляет отдельный локальный просмотр; это не зависимость от встроенной визуализации чата и не опубликованный сайт.
